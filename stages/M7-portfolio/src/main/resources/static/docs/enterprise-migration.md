# 企业平移说明（M7 Portfolio）

> 目标：向面试官 / 团队讲清——这套作品集不是"玩具 Demo"，而是**架构与语料解耦、每一层都有明确企业级替换点**的工程骨架。当前用轻量实现跑通全链路，换到企业环境只需替换对应层，主链路与观测/评估体系不变。
>
> 配套阅读：平台选型与 TCO 见 [`platform-compare.md`](./platform-compare.md)。

---

## 1. 一句话结论

**架构分层清晰、配置外置、旁路能力不侵入主链路**——所以它能从"本地学习版"平滑长成"企业生产版"：换语料源、换向量库、换模型端点、接企业内部工具，四层解耦，替换点明确、爆炸半径可控。

---

## 2. 四层解耦（核心）

| 层 | 当前实现（学习期） | 企业可替换为 | 替换方式 / 成本 |
|----|------------------|------------|----------------|
| **语料源** | `corpus/` 目录 Markdown | Confluence / 飞书 / 钉钉 / OSS / 数据库 / 工单系统 | 在 `IngestionService` 前加数据源适配器，切片/入库逻辑不变 |
| **向量库** | Qdrant（本地 gRPC 6334） | Milvus / pgvector / 云托管向量（如百炼知识库） | 面向 `VectorStore` 接口；改配置或换实现，检索/重排不变 |
| **模型层** | 百炼 DashScope（qwen3.8-27b + embedding + rerank） | 自建 vLLM / 其他云厂商 / 私有化模型 | 基于 `ChatClient` / `EmbeddingModel` 抽象，改 `base-url`/`key`/`model` |
| **Tool 抽象** | 本地 Tool 注册表（M4 预留） | 企业内部 API / MCP Server / 工作流平台 | 新增 `Tool` 实现并注册，`AgentOrchestrator` 无感调用 |

> 这四层正是面试必问的"可平移性"落点：**语料不进代码、检索不绑厂商、模型不锁端点、工具可插拔。**

---

## 3. 为何"可平移"（设计依据）

1. **管道 stage 化 + Micrometer 计时**：任一组件被替换后，各阶段耗时/计数依旧可观测，排障能力不退化。
2. **旁路能力不侵入主链路**：语义缓存、成本看板、双 RAGAS 评估都是"外挂"——关掉不影响问答，换上企业实现也不改主流程。
3. **LLM Wiki 存储可替换**：图谱当前落本地 `wiki/kg.json`，`KnowledgeGraph` 的存储层可平滑换成 Neo4j / 图数据库。
4. **配置外置**：端口、collection、检索参数、单价、Wiki 开关全部在 `application.yml` 的 `rag.*`，无硬编码。
5. **物理独立子项目**：每个 stage 可单独打包部署（容器化友好），M7 可作为对外演示入口。

---

## 4. 企业落地需补齐的能力（诚实清单）

学习版聚焦"链路正确 + 可观测 + 可评估"，上生产还需补：

- **鉴权 / 多租户 / 权限**：业务空间隔离、数据行级权限（百炼的"业务空间"即此类能力）。
- **高可用**：限流、熔断、重试、降级；模型与向量库多副本。
- **数据合规**：脱敏、审计日志、保留策略、数据不出域（可用"本地化 Hybrid RAG"：本地解析/嵌入、仅生成调云）。
- **容量规划**：向量库集群、索引重建、冷热分层。
- **质量门禁**：把双 RAGAS 接入 CI，作为回归门禁（指标不达标阻断发布）。

---

## 5. TCO 五项（引用 M6）

企业选型必须能随口讲清这五项成本：

1. **模型调用费**（token × 单价）
2. **向量集群 / 存储费**（规格 × 时长，或按 RCU）
3. **运维人力**（自托管的部署、升级、值班）
4. **合规改造**（私有化、审计、脱敏）
5. **扩容弹性**（峰值 QPS 与成本曲线）

> 学习期近乎零成本（本地 Qdrant + 按量百炼、用量小）；企业按规模在"托管 vs 自建"间权衡。

---

## 6. Build vs Buy 决策框架（引用 M6）

- **选平台（Buy）**：要快上线、团队缺检索/重排工程力、场景标准、合规可接受公有云。
- **选自研（Build）**：需代码级可控、数据不出域、有差异化能力（缓存/评估/知识图谱）、要作为技术资产。
- **混合（推荐）**：用托管模型 + 自研编排/检索/评估/Wiki——取"模型稳定"与"应用可控"之长。

---

## 7. MCP 扩展路径（本期不接入代码，仅说明）

M4 已在 `Tool` 抽象层为 MCP 预留解耦接口。若要"让自研 Agent 也能调外部工具"：

1. 实现 `McpToolAdapter implements Tool`（内部用 MCP client 与 MCP Server 通信）；
2. 注册进本地 `Tool` 注册表；
3. `AgentOrchestrator` 无需改动即可在 ReAct 循环中调用。

**为何本期不做**：引入新依赖与进程管理，风险大于当前演示收益。作为"企业对齐 / 作品集加分"的可选扩展，路径已明确。

---

## 8. 面试话术（电梯演讲）

> "这套系统我能讲清每一层：语料进来怎么切片、检索怎么融合重排、Agent 怎么防幻觉、成本怎么算、效果怎么评、知识怎么演进。它现在是本地轻量实现，但四层都解耦——换企业语料源、换 Milvus、换私有化模型、接内部工具，主链路和观测评估都不用重写。这正是一个 15 年 Java 后端该有的'可平移'工程能力。"

- [ ] 容器化与 CI/CD
- [ ] 合规（脱敏 / 审计 / 保留策略 / 数据不出域）
