# MySQL 索引基础

## 为什么用 B+ 树

B+ 树矮胖（千万级数据通常 3~4 层），每次查询只需少量磁盘 IO；叶子节点用双向链表串联，范围查询高效。相比之下哈希索引不支持范围查询，二叉树在有序插入下会退化成链表。

## 聚簇索引与回表

InnoDB 主键索引即聚簇索引，叶子节点存整行数据。二级索引叶子节点存的是主键值，命中后若需要的列不在索引里，要拿主键回聚簇索引再查一次，即"回表"。

## 覆盖索引

如果查询的列全部包含在二级索引中，就无需回表，称为覆盖索引。这是"按需建联合索引、避免 select *"的核心原理。

## 最左前缀原则

联合索引 `(a, b, c)` 相当于按 a、(a,b)、(a,b,c) 排序。查询条件必须从最左列开始连续命中；跳过 a 直接查 b 用不上该索引；范围查询后的列会停止使用索引排序能力。

## 面试常见追问

索引下推（ICP）是什么？——把 where 中索引能过滤的条件下推到存储引擎层执行，减少回表次数。
